# 长尾知识补偿驱动的个性化营养食谱系统 V1.0 用户使用说明书

## 1 启动

按照项目 `README.md` 安装前端依赖并构建，然后运行 `python app.py`。在本机浏览器打开 `http://127.0.0.1:8765`，无需登录即可进入体验工作台。首页展示食材、食谱、长尾食材和关联边的数量。

## 2 营养智能问答

在左侧导航选择“营养智能问答”，输入食材、营养目标或食谱问题。按 Enter 发送，Shift + Enter 换行。系统默认从当前食谱库检索并回答，在回复上标记“知识检索”；若后端已配置可用的本地 Ollama 模型，则回复标记为“本地大模型”。左侧“最近对话”可重新打开已保存的问答。点击“开启新对话”可开始新记录。

## 3 食谱推荐

进入“食谱推荐”，填写一餐的能量、蛋白质、脂肪、碳水、膳食纤维下限和钠上限。选择偏好食材和需要排除的食材，点击“生成推荐”。系统按综合分数排序，展示每份营养值和食材克数。若某一结果使用了长尾补偿候选，会显示候选关联及证据分数。该候选仅表示推荐线索，不等同于食材一定适合搭配。

## 4 知识图谱可视化

进入“知识图谱可视化”，选择默认 Food.com 或已上传的知识三元组数据集，检索实体与关系，查看局部图谱及来源。Food.com 展示真实食谱与食材组成关系，不提供关系置信度；上传的三元组保留其置信度、来源与原文证据。

## 5 数据管理

进入“数据管理”，选择符合页面示例结构的 JSON 文件。导入成功后系统自动刷新统计和食材列表。导入数据保存在本机 `data/current.json`。点击“恢复演示数据”可删除当前导入文件并重新加载演示样例。

## 6 数据注意事项

食材营养值必须以每 100 g 为单位；食谱中的 `grams` 是整道食谱的总克数，`servings` 是份数。数据缺失、食材 ID 引用错误或营养值为负数时，系统拒绝导入。演示数据仅用于功能展示，不适用于个人医疗或膳食决策。
