# 长尾知识补偿驱动的个性化营养食谱系统 V1.0 软件设计说明书

## 1 软件概述

本软件面向营养食谱研究与教学演示。用户打开工作台后，可保存本地营养问答记录，查看食材长尾分布和稀疏关联的补偿候选，并设置每餐营养目标和食材偏好，获取附有解释的食谱排序结果。软件采用本地浏览器页面，不要求云服务。

## 2 运行环境与架构

前端由 Vue 3、TypeScript 和 Vite 构建；后端由 Python 3.10+ 的 `http.server` 实现。前端构建产物由后端提供，双方通过 JSON HTTP 接口通信。食材与食谱以 JSON 文件保存于本机；用户、会话、问答以 SQLite 保存。默认只监听 `127.0.0.1:8765`。

## 3 模块设计

### 3.1 账户与工作台模块

当前版本打开页面后自动创建本地体验会话，不显示登录页面。后端保留可扩展的账户接口：密码经随机盐与 PBKDF2-SHA256 处理后存储；会话使用随机令牌，浏览器 Cookie 设为 HttpOnly 和 SameSite=Strict。工作台提供功能首页、智能问答、食谱推荐、知识图谱和数据管理入口。

### 3.2 智能问答模块

系统从问题中提取营养目标和已知食材名称，检索当前食谱库，按每份营养值生成参考回答。若通过环境变量配置本地 Ollama 模型，则将候选食谱和程序计算的营养值作为上下文调用 `/api/chat`，并标注回复来源为“本地大模型”。模型不可用时回退至知识检索模式。回答与问题保存在当前账户下。

### 3.3 数据管理模块

导入时检查食材和食谱 ID 唯一性、食谱食材引用、份数和克数、六维营养值的类型和非负性。验证成功后以临时文件替换当前数据文件，避免部分写入。恢复演示数据时删除当前导入文件。

### 3.4 长尾识别模块

统计每个食材在多少道食谱中出现，并以出现频次的第 25 百分位作为当前数据的长尾阈值。阈值和食材频次可在页面查看。该阈值是产品默认参数，研究实验可按数据分布重新设定。

### 3.5 知识补偿模块

食材之间的真实共现来自同一道食谱。对于长尾食材，系统计算它与更高频食材的相似度：营养向量余弦相似度占 55%，食材类别一致占 30%，名称词重合占 15%。当相似度至少为 0.65 时，将相似食材的共现对象作为长尾食材的候选关联，并赋予弱化后的证据分数。真实边标记为 `observed`，候选边标记为 `inferred`。系统不把候选边当作已验证事实，也不借此推断营养含量。

### 3.6 营养计算与推荐模块

每份营养值 = 各食材每 100 g 营养值 × 食材总克数 ÷ 100 的总和 ÷ 食谱份数。推荐前排除含用户禁用食材的食谱。能量、蛋白质、脂肪和碳水按相对偏差计算；膳食纤维按最低目标、钠按最高限值计算。营养匹配分数占 70%，偏好匹配分数占 30%。直接包含偏好食材时给出强证据；长尾食材的补偿候选仅提供弱证据。结果展示评分、每份营养值和补偿来源。

## 4 数据结构

`Ingredient` 包含 `id`、`name`、`category`、`per_100g`。`Recipe` 包含 `id`、`name`、`servings`、`ingredients` 数组。每个食谱食材记录包含 `id` 和 `grams`。六个营养键为 `energy_kcal`、`protein_g`、`fat_g`、`carbs_g`、`fiber_g`、`sodium_mg`。

## 5 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/summary` | 获取数据规模和阈值 |
| GET | `/api/ingredients` | 获取食材列表及频次 |
| GET | `/api/ingredient/{id}` | 获取食材营养值、相似食材和关联 |
| GET | `/api/recipes` | 获取食谱基本信息 |
| POST | `/api/recommend` | 根据目标与偏好生成推荐 |
| POST | `/api/import` | 导入并验证数据 |
| POST | `/api/reset` | 恢复演示数据 |
| POST | `/api/register`、`/api/login`、`/api/logout` | 账户操作 |
| GET | `/api/me` | 查询当前账户 |
| GET | `/api/conversations`、`/api/conversations/{id}` | 查询当前账户的问答记录 |
| POST | `/api/chat` | 知识检索或本地模型问答并保存 |
| GET | `/api/model/status` | 查询本地模型状态 |

## 6 技术边界与后续扩展

V1.0 使用轻量的营养与文本相似度，不含预训练 BERT 模型或 UnKGE-BCKC 的聚类、残差补偿和对比学习训练流程。Ollama 接入代码已实现，但模型权重和运行服务须另行配置。若后续做论文级实验，应增加可重复的长尾分层评估、训练/测试隔离、离线 BERT 嵌入、消融实验和人工审查的补偿边。Nutri20K 正式数据中可能没有当前接口所需的全部克数或营养密度，接入时需先完成合法的数据转换与质量检查。
